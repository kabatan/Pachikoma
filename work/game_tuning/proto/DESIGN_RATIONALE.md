# ゲーム設計の根拠：既存ゲームと消費者心理 → 何を見せ・何を触らせるか → 規則

方針（本人の言葉）: 実際に運ゲーでなくてもよい。『運ゲーでないように錯覚』させる。調整はデータを追うのでなく、既存ゲームと消費者心理の分析から設計する。
出典は PachikomaDesign/research 以下（ラベルは調査側の [確認]=本文を読んだ／[要旨]／[二次]／[計算]／[推測]）。数値実験は『この設計が物理上成り立つか』の裏付けにだけ使う。

## 1. 既存ゲームから学ぶこと
| 既存例 | 学ぶこと | 出典 |
|---|---|---|
| パチスロ技術介入機（うみねこ2 98.4→103%、ディスクアップ2 103.0%） | 腕の実差は小さい(+2.4〜4.6pt)のに、見た目の手応えは大きい。押した動作と画面の動きが一致すれば制御感が出る | illusion_machines §0, §2-1 [確認] |
| パチンコの止め打ち・ひねり打ち | 実効果は数十玉。儀式化できる再現可能な動作が『手を入れた』感を作る | §2-4 [確認] |
| パチンコのリーチ/保留色 | 結果は先に決まり、期待度を段階で小出しにする。目盛り(約3%/36%/92%)は機種内で一貫して使う。目盛りが崩れると信頼を失う | §0, §3-3, §3-4 [確認] |
| スマートボール（100円25玉、入賞5〜15玉） | 持ち玉の増減で時間が伸縮する。パチコマに最も近い先例 | §5-5 [確認] |
| クレーンの確率機・客ごとの出し分け | 悪例。取れる設定を見せて不可能にするのが詐欺。偽の寄せ・客別補正はやらない | §5-4 [報道] |
| 英RTS 7C／豪州のニアミス規制 | 外れを別の外れに差し替える偽ニアミスは禁止。『リーチ』は規則上の状態なので別物 | §0 [確認] |

## 2. 消費者心理から使えるもの・使えないもの
使う（堅い土台は4つ。§0 結論）
1. 本物の小さな制御: 実際に確率が変わる選択だけが期待を上げる。見かけだけの選択は効かない(Klusowski 2021, 17実験N=10,825) [確認]。→ 『どの口を狙うか』『いつ勝負か』は本当に配当と入りやすさが違う選択にする。
2. 押してから起きるまでの即時の因果: 押下→発射100〜150ms、痕跡0.3秒。『ジャスト』など結果と無関係な演出は偽の腕前なので置かない(§2-1)。
3. 物としての手触り: 実物の玉が皿に見える。所持が所有感を作る(Reb & Connolly 2007、効果は小) (§1-1)。
4. 目標を参照点にした『あと少し』: 賞ラインの27玉以内だけ『あとN玉』(§1-2, §4-4)。目標勾配(Kivetz 2006)。
ニアミスは『次の1球への意欲』に効く(Clark 2009=自分で選んだ試行のみ、Palmer 2024=1/3頻度)。セッション延長は不安定(Pisklak 2020, Stange 2020)。→ 惜しいは出すが、全勝負球の25〜35%、物理由来の本物だけ(R-22)。
負けに勝ち演出(LDW)は禁止: 祝うのは持ち玉が実際に増えた時だけ(Harrigan 2011, Dixon 2014, Scarfe 2020)。
使わない（再現が弱い/割れている）: 選ぶだけの支配の錯覚、ピーク・エンド、小額の損失回避、サンクコスト、早期大勝ち仕込み(§0表)。『出来すぎ』は信頼を落とす。

## 3. 設計：触らせるもの／見せるもの
触らせる（本物の制御）
- 狙い位置: 『腕は玉が入るまで、運は入ってから』(game_control)。同じ位置を狙えば同じ傾向になるなめらかさが学習の前提。
- 勝負のタイミング: 1〜3灯の勝負成功は『回収』で小さく、4灯が本当の押し引き(今勝負か1球粘るか)。
- 未点灯の口の選択: 配当と入りやすさが実際に違う口どうし(ただし入りやすさは全員同じ盤面)。
- 追加100円: 事実だけ。灯と持ち玉は凍結のまま。煽り文句なし。
見せる（正直な情報）
- 狙いの予測は物理から計算した値だけ(R-06)。持ち玉は実数。灯。5灯は『リーチ』として残り1穴を脈動。
- 惜しい: 勝負球が外れ、玉が未点灯口の入口線を内向きに通過してから別の口へ跨いだ時だけ(波紋1回)。
- 『あとN玉』: ≤27のときだけ実数で。
やらない
- 客ごとの補正、終盤保護、偽ニアミス、LDW、煽り、露骨な軌道操作、可動小道具、スローモーション。

## 4. 設計から規則への落とし込み（数字は設計の帰結。目的ではない）

|---|---|---|
| 一連の体験は100秒/追加ありで2分に収める。演出は時計を止めてよいが総量に予算 | 基本制限を短くし(80秒台見込み)、停止の合計に上限(ClockStopBudget)。JP/重複ルーレット/昇天/4灯合図/大成功リセットが対象。数え上げ・皿注ぎ・余韻は時計を動かし入力も塞がない | 本人最新指示、R-07 |
| 賞境界は『谷』にする | 賞閾値を最終持ち玉の山の少し上に置く。境界直下[B-27,B-1]に10%以上、1玉差で賞が変わる質量≤3% | R-01, 目標勾配 |

## 5. 正直な弱点（まだ解決していない）
- 現行の盤は狙いが3〜4ゾーンにしか効かない(1200玉×81狙い測定)。『狙えば入る』『腕で口を選べる』感が弱く、運ゲーに見える恐れがある。→ なめらかさ(隣接TV)と最良口の入り率で盤・ジッタを見直し中(solの読みやすさ測定、結果待ち)。
- 通しプレイ(bot)で体感157秒、毎球の全画面カットインで狙った結果が見えなかった。→ 演出側に尺上限を依頼済み(入賞0.6s等)、基本制限の短縮と停止予算で収める。
- 4灯以上に届く頻度(ハイライトの出やすさ)は典型プレイで少ない恐れ。R-08で計測して賞境界・リセット重みで調整。
- 上の数値(80秒台、27玉等)の多くは研究上の推測。実客での試遊(文化祭前)で検証が必要。

## 6. 玉の落下を遅くした理由と方法（2026-10-17、公開版の試遊を受けて）
問題: 公開版の玉は発射から入賞まで平均0.72秒（p10 0.47 / p90 0.95）で落ちていた。60fpsでも575fpsでも同じ（シミュ時間÷実時間=1.00）で、フレーム依存ではなく設計どおりの実寸の落下だった（盤約30cmを、釘が疎なので自由落下に近く落ちる）。本人の言葉は「玉の落下を追うのが楽しみとして非常に重要。連射できるのだから落下に余裕を持たせてよい」。
決め方（データ最適化でなく既存の事例と心理から）:
- 調査 `game_pacing`: 通常球は約2.1秒、釘ゾーン約1.3秒が目安（玉を目で追え、1球ごとの結果を味わえる長さ）。パチンコの玉は釘が密で数秒かけて落ちる。
- ピンボールの盤は約6.5°傾いており、玉の有効重力は約1.1 m/s²。落下を0.35倍の時間にするのは有効重力 9.81×0.35² ≒ 1.2 m/s² で、ピンボールと同じ手触り（玉が軽く、目で追える）。
- 案A「盤上の玉の時間だけ伸ばす」を採用。軌跡と入賞口は全球同じ（40球で確認、`physics/board_timescale_test.mjs`）なので、これまでの盤・ジッタ・規則の調整値がそのまま有効。発射器・皿・規則の時計は実時間のまま。
- 案B「釘を増やす／傾ける／反発を変える」は実機に近いが、入賞分布が変わり、3Dの静的層（釘）の作り直しと再調整が要る。時間が足りないので採らない。実機の見た目の自然さは、玉の軌跡が物理どおり（反発・回転はそのまま）であることで保つ。
結果: 平均2.03秒（1.3〜2.7秒）。ただし実機の通し録画では、玉が暗い背景に沈んで見えにくい。落下を目で追えるかは玉の見えやすさ（演出・描画側）にも依存する。
副作用と再較正: 発射は1球ずつ（着地まで次を打てない）なので、1回に打てる玉数が約17%減る（13.8→11.5発）。時間は75秒（+5秒）、賞閾値をC8/B24/A46に直した。詳細は `RULES_FINAL_V2.md` 末尾。

## 7. 初見に優しいテンポ（2026-10-17）
本人の言葉は「テンポ、ゲームの進行が速すぎる。初見の人に優しく、ゲームを楽しむ余裕がある設計」。
根拠:
- 玉の落下: 通常球は約2秒（§6）。パチンコの通常変動は10〜15秒だが、毎球の結果はすぐ分かる（調査 game_pacing）。落下は目で追え、1球のサイクルは約3.5秒（狙い待ち0.8＋落下2＋ロック0.45）。
- 点灯は1.0秒以上見せる。ただし入力は0.45秒で再開（演出を重ねてよい）。入力を止める時間を短く保つ(R-04)ことと、結果を読む時間を取ることを両立するため、「見せる長さ」と「入力ロックの長さ」を分けた。
- 重複ルーレットは灯数に比例（1〜2灯1.0〜1.5秒、3灯1.5〜2.2秒、4〜5灯は規則側ロック6/12秒で時計停止、停止の予算10秒）。結果に依らず長さを同じにする（調査 game_pacing §重複ルーレット）。
- 時計は、払い出し(約1.7秒)が終わってから動く。ユーザーの旧レビュー「チケット→GET→皿が満ちる→スタート、時計はスタートから」に合わせる。howto中も止まる。
- 時間枠: 平均で100秒/追加ありで2分（howto込み）。余裕を持たせると超えるため、基本72秒・追加25秒・継続選択8秒に調整した（RULES_FINAL_V2.md 追記2）。超える場合は私から報告し、勝手に超えない。
- 各場面の最短/最長と入力ロックの上限は EFFECTS_DESIGN_MEMO.md の表。
未確認: 実際の初見の人が理解し、玉を追えるか（試遊が必要）。howtoは一度見れば飛ばせるが、初見が7.6秒で読み切れるかも未確認。

## 8. 追加100円の直後に最初の1球が待たされる問題（2026-10-17、通しプレイで発見）
持ち玉が尽きて100円を足すと、物理側は皿に玉を注いでから昇降管を上らせるため、最初の1球が7〜9秒待たされた（再現: loan_reserve_test.mjs、実プレイ記録で落下8.6秒）。時計は動いているので、初見の人には「壊れた」と見える。
対処: 最初の貸しと同じく、昇降管の予備球(最大5個)を追加の瞬間に物理側へ用意する（`reserveForLoan`）。払い出しの演出（皿へ注ぐ）は変えない。修正後の通しプレイで最大落下は3.4秒、台帳の食い違い0。

## 9. 落下中にも次の球を撃てる（2026-10-17、本人の指示）
本人の言葉は「落下しきるまで次を撃てないのはストレス。スムーズに感じられるように」。落下を目で追えるよう遅くした（§6）ため、1球ずつの待ちが約3.5秒に伸びていたのが原因。
根拠（1行）: 実機のパチンコは法規で約100発/分（0.6秒間隔）に上限があり、遅い玉を何個も同時に追えること自体が楽しさの源（盤上に常に動きがある）なので、間隔0.6秒・同時3球とした。落下は平均2.0秒なので、0.6秒間隔で連打すると盤上は約3球で釣り合い、目で追える数に収まる（4球以上は追えなくなる）。
- 間隔は、押した→出たの即時因果を壊さない範囲で、連打が無制限にならない最低限（速すぎる連打は狙いを雑にし、「運ゲー」に寄る）。
- 勝負だけは1球ずつにした: 勝負は「灯を賭ける1球」なので、結果の読みを他の玉と混ぜない（演出が重ならず、成否が一目で分かる）。そのため、勝負ボタンを先に押したら、盤上の玉が着き終わるまで新しい玉は撃たず、着いたら自動で宣言する。
- 「次を撃てない」不満の芽をさらに潰すため、間隔待ち（残り0.3秒以内）の先押しは捨てずに保持し、押した瞬間の狙いで撃つ。
- 副作用: 1回に撃てる玉が増え、賞が上振れするので閾値と追加時間を較正し直した（RULES_FINAL_V2.md 追記3）。
未確認: 実際の客が同時発射でどれだけ速く押すか。盤上の玉が3つのときに狙いと結果の対応が分かるか（玉の見えやすさに依存）。勝負ボタンを先に押してから宣言されるまでの数秒に、反応がなくて壊れたと感じないか（演出側に先押しの受け付けを示す小さな反応を依頼する）。
- 賞の目安は「結構上手い人」基準（本人の指示）: 初心者込みの混合ではなく、狙いがかなり正確な人（Regular/Expert）がA賞を約7%取れるように閾値を較正した（C9/B35/A51/S165/SS543）。このとき混合ではA約4%。詳細は RULES_FINAL_V2.md 追記4。
- 補給の見た目: 皿に見える玉を増やすため、昇降管の予備球を開始時4個（シャトル含む）・以後最大3個にし、昇降管を0.4m/sに上げて0.6秒間隔の連射でも詰まらないことを確認した（physics/rapid_supply_test.mjs）。
