# 演出担当への設計メモ（改訂 2026-10-17：初見に優しいテンポ／各場面の最短・最長／入力を受け付けない時間の上限）

根拠は PachikomaDesign/research の要件 R-01〜R-25（特に game_pacing）と本人の言葉。数値実験ではなく設計意図。
演出の見た目は演出側で決める。調整側は「感じさせたいこと」「尺の範囲」「入力を止めてよい上限」「発火条件(イベント)」だけ持つ。

## 変わったこと（前版との差）
- **玉の落下が約2秒になった**（盤上の玉だけ0.35倍。平均2.0秒、1.3〜2.7秒）。玉は発射から入賞まで目で追える。**落下中に盤面を隠す演出を出さない**。
- 1球のサイクルは約3.5秒（狙い待ち約0.8＋落下約2＋点灯の入力ロック0.45）。毎球の演出は、この間に次の狙いを邪魔しない。
- 時間枠は 100円=約85秒、追加ありで約113秒、混合の平均で約95秒（継続選択込み、howtoは別。howto7.6秒を足すと約92秒／約120.5秒）。
- **時計は、払い出し(ticket→GET→皿に玉が落ちる約1.7秒)が終わって「スタート!」が出た時点から動く**（`ClockStartsAfterLoan`。howto中は止まる。追加100円も同じ）。

## 大原則（変わらない）
- 本人の方針は「運ゲーでないように錯覚させる」。**押した→起きた**の即時因果と、**狙いが効いた**手応えが最優先。
- 実際に増えた時だけ祝う（LDW禁止）。偽の惜しいも禁止。負け・回収(1〜3玉)に勝ち演出を付けない。
- 演出は結果を**先に**見せず、玉が入った瞬間に起こす（落下中は盤面と玉を見せる）。

## 今回の見直しで、現行specから変えてほしいところ
1. **毎球の点灯**: 点灯の演出は1.0秒以上見せる（入力は0.45秒で再開）。今の0.8秒の山場は1.0秒まで伸ばし、灯った口そのものを主役にする。落下中に画面が覆われている場面は避ける（録画では落下に重なる全画面の光があった）。
2. **同じ穴(保護中)**: 0.35秒は短すぎて何が起きたか分からない。0.5〜1.4秒、静かに。
3. **4灯・5灯**: lamp4 4.1秒、lamp5 3.4秒は最長3.0秒に。入力は0.45秒で再開する。
4. **重複ルーレット**: 現行8.3秒＋ascend 5.0秒は、1〜3灯では長すぎる(入力ロックは0.5秒、玉の落下中に重なる)。1〜2灯は1.0〜1.5秒、3灯は1.5〜2.2秒。4灯・5灯だけが規則側で入力ロック6秒/12秒(時計は止まる、予算10秒)なので、そこで長い演出を使う。
5. **勝負の落下はスローにしない**(物理がすでに約2秒)。勝負球の接近だけ延ばす案は、調整側で物理の時間を位置で切り替える形で検討中（結果には依存させない）。
6. **玉が見えること**: 玉が暗い紺の背景で黒い輪にしか見えない場面が多い。落下する玉の縁・光・淡い軌跡など、玉の見えやすさを上げる（描画・演出側）。
7. 初見の案内(tut_*)は、玉の落下を隠さず、盤面の外(液晶左上・ボタン側)に出す。

## イベントとパラメータ
- `fail`: `near_miss`(R-22: 未点灯口の入口線を内向きに通過してから仕切りを跨いで別の口へ落ちた時だけ true) / `target` / `unlit`。
- `result` / `finish_count`: `to_next`, `next_rank`, `next_threshold`。`to_next>27` では表示しない。
- 皿への注ぎ: `awardToTray(count,{rate})`。`setAwardHold(true, 秒)` の上限は秒数どおり。Result/Continueに入ると自動解放。JPは14秒まで。
- 賞閾値は C8 / B24 / A44 / S165 / SS543、基本時間72秒、追加25秒、継続選択8秒（`rules_final.json`）。表示に使う数字は規則から読む。

## 演出側への依頼
1. 上の最短/最長に収める。ロックが終わったら次の操作を必ず受け付ける。
2. 落下中の玉を隠さない。玉を見えやすくする。
3. 「惜しい」は near_miss===true のときだけ、波紋1回。
4. 追加案は、このメモに反応する形で調整担当へ。数字は調整担当が持つ。
